# Порядок работы с PR

**1.** Чтобы PR был принят, он должен:
   - получить два аппрува от сотрудников отдела разработки MPP Postgres компании Яндекс;
   - успешно пройти тесты.

**2.** Проверяющий должен:
   - прочитать описание PR и оценить идею исправления на побочные эффекты, оптимальность и полноту устранения проблемы (патч должен закрывать проблему полностью, а не отдельный частный случай);
   - убедиться, что PR соответствует [требованиям к оформлению](PR_requirements_ru.md);
   - прочитать изменения кода и попробовать обнаружить в них ошибки, неоптимальности и побочные эффекты.

**3.** Проверяющему рекомендуется:
   - воспроизвести проблему, используя описание PR, и убедиться, что она решена;
   - пройтись отладчиком по измененным участкам кода для лучшего понимания работы нового алгоритма;
   - попробовать найти не учтенные автором смежные проблемы (имеющие ту же причину), которые не исправлены в данном патче, но должны быть исправлены в нем.
